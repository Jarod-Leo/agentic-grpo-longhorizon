# E12：GRPO＋Agent-OPSD-FB 实施与 CPU 验收

E06、E07分别通过CPU作业166809/166814后实施E11；E11已通过CPU作业166829（153项测试），现在开始E12。本轮只做实现和CPU测试。

## 方法与最小改动

复用E11的F2反馈、自教师批次构造与每批更新前冻结评分；从官方Qwen3-8B及相同LoRA初始化独立开始，不续训其他实验。只增加配置与薄入口，不复制训练/评测或Slurm代码。目标为：

$$
L=L_{GRPO}+0.3L_{OPSD}.
$$

GRPO使用二元终局奖励和既有组内标准化；OPSD使用固定自教师/old sampled-token差及相同assistant mask，单独计算并加权，不做组内标准化。即使GRPO组内全部成功或失败，已验证的反馈自蒸馏分支仍可提供梯度。两个分支基于同次学生forward。

0.3是当前未调优默认值，便于与E07同系数比较，不宣称自教师与32B外教师信号尺度相同或系数已最优。原首版计划建议自蒸馏独立小网格；本轮CPU实现不进行调参，也不访问test。后续如果调整系数必须预先记录train侧依据。

E12与E11的完整Hydra配置除RL/蒸馏系数外一致，沿用40/10划分、200步、4×8轨迹、32768token动态微批、每50步保存到HDD和每100步train评测。E12复用单卡共享壳，当前不提交GPU。

## CPU验收

复跑前三组回归；用自教师实际生成的token分数检验GRPO与0.3倍OPSD贡献、全失败GRPO零信号时自蒸馏仍有梯度，以及系数0严格退化GRPO且不调用自教师。确认自教师在optimizer更新前完成、冻结分数跨actor更新不变，两个配置仅有目标系数差异。主线程负责配置、验收与发布，worker补充组合路径测试，explorer审查共用方法。

GPU显存、FlashAttention/去padding动态微批执行、真实F2教师质量、训练耗时和任务收益不在本轮CPU验收结论内。
