# 实验 C：GRPO + 局部分支优势

## 当前状态与后续恢复约定

本文保留实验 C 的原方案、已执行验证和环境修复后的恢复方案，后续继续此方向时以本节和文末“重启路线”为准。当前只记录方案，不据此启动新的训练或评测。

- **研究问题**：GRPO 的整条轨迹奖励难以区分关键动作的贡献；C 在同一个真实环境状态下比较多个候选动作的后续成功率，形成局部动作优势。
- **已完成**：快照/恢复、候选与续写诊断、CPU 检查、GPU smoke，以及修复终止语义后的 K=4、M=8 信号诊断。
- **尚未完成**：局部优势接入 actor loss、20–30 次更新对照、从 base 开始的正式 200 次更新实验。C 至今没有执行梯度更新，不能称为已经训练完成的模型。
- **当前结论**：旧 E01 step200 上，修复后的 44 个有效前缀全部同成同败，局部优势为零。因此暂缓 C 的训练，保留实现与产物。
- **起点调整**：旧 E01 step200 只保留为历史诊断起点。后续优先在正确环境下从原始 Qwen3-8B 建立新的 GRPO 基线，再选取该基线的完整 checkpoint 验证 C；不能默认继续沿用旧 E01 step200。
- **数据边界**：沿用 40 个 train / 10 个 test，无 dev。分支设计、候选数和局部权重的调整只使用 train；test 用于预先约定的最终比较。

## 目标与边界（原始验证方案）

研究同一中间状态下的候选动作比较，是否改善长链路工具调用的信用分配。
本轮授权开展验证实验，不启动从 base 开始的 200 次更新正式训练。
初始诊断冻结 E01 step 200，仅使用原有 40 个 train 任务；10 个 test 不参与方法选择。

## 分支方案

在 assistant 生成前保存完整状态。每个分支点采样 K=4 个候选 assistant turn；
每个候选只生成一次，固定其 token 和工具调用，再从执行该动作之前的相同状态独立续写 M=2 次。
分支保留已执行工具造成的数据库变更、用户历史、动作历史及已用轮数/token 预算，不能重新获取完整预算。
首版动作粒度为完整 assistant turn，不声称能区分同一轮内多个工具调用的贡献。
不同候选允许相同文本，不通过拒绝采样强制多样性。

$$
\widehat Q_{t,k}=\frac{1}{M}\sum_{m=1}^{M}R_{t,k,m}
$$

$$
A^{\mathrm{local}}_{t,k}=\widehat Q_{t,k}-\frac{1}{K-1}\sum_{j\ne k}\widehat Q_{t,j}
$$

后续训练拟采用 $L=L_{\mathrm{GRPO}}+\lambda L_{\mathrm{local}}$，初始候选权重为 0.25。
局部项只覆盖候选动作 token；前缀及后续续写不参与该项损失。
冻结诊断只计算候选回报与局部优势，不能替代梯度 mask/优化器集成验收。

## 验证顺序与门槛

1. CPU：验证数据库/历史/状态隔离，候选固定后独立续写，轮数与预算继承，失败传播和资源清理。
2. GPU smoke：单卡 Pro6000，少量 train 分支点；核对 K×M 完整性、二元奖励、执行成本和日志。
3. 固定模型信号诊断：计划 80–120 个 train 分支点。记录有效分支率（候选平均回报不全相同）、候选重复率、同候选续写差异、tokens/API/时间。
4. 对部分分支点额外续写确认动作排序稳定性。有效分支率约 20% 仅是预先提出的筛选门槛，不是统计显著性标准；M=2 的差异不足以证明有效信用信号。
5. 原计划在信号及成本通过后，从同一 E01 完整 checkpoint 做 20–30 次更新的 C/普通 GRPO 对照。环境故障确认后，此起点已改为正确环境下重新训练得到的 GRPO checkpoint，详见文末重启路线；两组恢复的模型、优化器状态和用户模拟器必须一致。

任何阶段只运行完成，都不等于后续阶段通过。若所有候选同成同败，局部优势为零；若续写随机性大于动作差异，应调整分支位置或 M，再考虑训练。
短程训练验收关注有限 loss/梯度、目标 mask、KL/长度/工具行为和无明显退化，不要求短期 train 成功率显著上升。

## 正式实验（尚未启动）

通过上述验证后，先做原始 Qwen3-8B 短 smoke，再进行 base 同起点的普通 GRPO 和 C 各 200 次实际更新。

测试不做分支搜索，报告 Pass@1、Pass@4、Pass⁴，以及逐任务结果和交互成本。

复用当前 veRL 服务、共享评测入口、TauBenchAgentLoop 工具执行与奖励计算。

## 重启路线：先建立正确基线，再验证局部优势

本节是环境故障和全模型复评之后的后续建议，具体训练启动仍以用户后续指令为准。原始研究问题与局部优势公式保留，调整的是验证起点和分支位置。

### 1. 检查基础任务执行并重新建立 GRPO 基线

原始 Qwen3-8B 在当前协议下 train 成功率6.25%、test成功率1.25%。在投入正式重训前，应检查模型输入、工具schema、真实工具返回内容与上下文截断、轮数限制，确认低分是否还存在执行层原因。不能仅以作业退出码或二元奖励合法作为全部正确性的证明。

随后建议从原始 Qwen3-8B 开始，在修复后的环境中做20–30次更新的普通GRPO短程验证，检查首次终止结果、梯度、工具错误、转人工及成功轨迹的实际数据库操作。通过后再推进200次更新基线。旧checkpoint、旧优化器状态与可能被错误奖励污染的成功轨迹不作为这个新基线的初始化或训练数据。

### 2. 在可靠 checkpoint 上重做冻结分支诊断

使用上述新基线的一个明确记录的checkpoint，冻结参数，只使用train任务。该checkpoint尚未产生，不能把它与旧E01 step200混为一谈。

优先调整分支位置：从固定第2/4/6轮，探索第一个有实际选择空间的工具动作之前，或发生不可挽回的数据库写入/终止动作之前。必须在动作执行前保存状态；已经终止的状态不能再分支。具体前缀选择规则应在train上确定并记录，不能按test结果挑选。

分支执行流程保持为：

1. 保存动作前的数据库、对话历史、环境动作历史、策略前缀token以及剩余轮数/token预算。
2. 当前策略在相同前缀下生成K=4个候选assistant turn；每个候选只生成一次，固定其token和工具参数。
3. 对每个候选，从相同动作前快照恢复M个独立环境，先执行固定候选，再由同一策略继续完成任务。MiMo后续回复具有随机性，环境快照不能恢复远程模拟器的随机状态。
4. 第一次环境终止时停止，使用原始tau-bench二元结果作为该后缀的回报。参考答案动作只用于环境评分，不能注入候选或策略上下文。
5. 计算候选平均回报与leave-one-out局部优势。按完全相同的候选token合并诊断统计，避免把同一动作的续写噪声误当成动作差异。

K4/M2可用于低成本工程smoke；信号确认可采用已验证过的K4/M8。若仍然所有候选同成同败，应检查起点、前缀是否已经决定结果和候选是否有实际行为差异，不能只通过增加M宣称方法有效。

### 3. 通过哪些条件才接入训练

| 检查层次 | 进入下一阶段的条件 |
| --- | --- |
| 执行正确性 | 状态隔离、固定候选、预算继承、完整K×M数据、二元回报通过检查；终止后生成、工具调用、用户API请求为0 |
| 局部信号 | 一批含不同候选动作的前缀出现非零优势；约20%有效分支率只是原先提出的描述性初筛值，不是统计显著性保证 |
| 重复稳定性 | 增加或拆分后缀样本后，动作优劣在有信息的前缀上基本稳定，报告平局、无信息组和比较数量；当前M8的0/44不满足此条件 |
| 交互成本 | 单独报告新增候选/后缀数、MiMo请求与token、策略生成token、GPU时间，成本在事先确定的预算内 |
| 训练集成 | 局部loss/梯度有限；前缀和续写不进入局部loss，只有候选动作token参与；log-prob、mask、批次归一化和checkpoint恢复正确 |

动作排序稳定性尚无已验证的固定数值门槛。后续应在新诊断前明确报告方式；不能把“工程验收通过”写成“C验证成功”。

### 4. 短程对照与局部损失

从同一个新GRPO完整checkpoint分别初始化普通GRPO对照和C，先比较20–30次实际参数更新；模型、优化器状态、训练任务采样和模拟器配置保持一致。

保留普通GRPO的任务级优势，C额外引入局部项：

$$
L = L_{\mathrm{GRPO}} + \lambda L_{\mathrm{local}}, \qquad \lambda = 0.25
$$

0.25是待验证的初始候选值。局部项只更新候选assistant turn的动作token，前缀以及用于估计回报的后续续写不参与该项loss。实现时复用veRL策略更新及既有mask能力，另行验证梯度归属；当前冻结诊断代码尚未实现这个actor训练项。

根轨迹仍为每步4个任务×8条轨迹。额外分支不冒充原有32条轨迹内的免费计算；相同更新数比较之外，还应比较相近交互成本下的普通GRPO。

### 5. 正式实验与何时暂停这个方向

短程执行和信号验证通过后，正式方法比较应从相同的原始Qwen3-8B起点开展普通GRPO与C各200次实际更新。原定每50次更新保存checkpoint、每100次更新评测train；提交前重新核对存储位置、容量和GPU/交互预算，最终按固定协议评测test。多个种子与相近交互预算对照用于进一步确认效果。

评测时使用训练后的策略直接完成任务，不使用局部分支搜索。报告任务宏平均Pass@1、Pass^4、辅助Pass@4、逐任务成功情况及额外交互成本。

若更换为可靠起点并调整前缀后，候选仍然没有稳定的回报差异，或获取信号的成本明显不合理，则暂停C并记录负结果。当前0/44说明的是旧E01起点加固定锚点方案未获得信用信号，尚不足以否定整个局部信用分配方向。
